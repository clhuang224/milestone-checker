# 提案:add-assessment-sessions

## 為什麼要做

規則現在用**今天**推算年齡——`case-detail` 把 `todayISO()` 餵給 `buildFacts()`。實務上這是錯的:

> 寫報告的時間跟評估的時間可能不是同一天，年齡會有差異。

一個孩子在 3 歲 11 個月被評估，報告兩週後才寫，系統會用 4 歲 0 個月去跑規則——「四歲以上」這種年齡條件就會給出跟當天現場不一樣的結論。年齡條件愈多，這個偏差愈危險。

同時暴露第二個缺口:**早產兒沒有矯正年齡**。足月與 32 週早產同樣出生 18 個月，發展期待差了兩個月，拿實齡去比會系統性高估早產兒的落後。

## 要做什麼

- **評估場次**:新增「一次評估」這個實體，帶自己的評估日期。觀察項目與構音音對都掛在某一次評估底下，同一個個案可以有多次評估。
- **年齡以評估日為準**:規則事實與報告草稿一律用該次評估的日期推算年齡，不再用今天。
- **矯正年齡**:個案可以填出生週數，系統推算矯正月齡;規則事實同時提供實齡與矯正齡，讓規則自己選要用哪一個。
- **資料版號升到 v3**,舊資料作廢——沿用上一個 change 已經確立的 PoC 取捨。

## 這次不做的事（範圍外）

- **不做評估之間的比較/進步追蹤**:這次只做到「資料掛在某次評估底下」與「用當次日期算年齡」。跨場次的趨勢圖表另外開。
- **不做吞嚥測試記錄、建議目錄、言語分級量表**:這三塊都會掛在評估場次底下，所以先把地基做完再做，避免做完又回頭改。
- **不做資料遷移**:PoC 階段，升版就是清空。
- **不自動判斷該用實齡還是矯正齡**:兩個都放進事實裡，由規則作者決定。系統替使用者選錯年齡基準的代價，比多一個欄位高。

## 技術方向

矯正年齡的適用期上限**先設 24 個月矯正齡**，超過就回實齡。這是常見慣例，但不同單位有用 2 歲也有用 3 歲的，屬於**待治療師審核的佔位數字**，要在程式碼裡標註清楚。

`ArticulationSubstitution` 會同時帶 `caseId` 與 `assessmentId`。這是刻意的反正規化——現有程式碼大量用 `caseId` 篩選，留著省掉每次 join——要在型別註解裡寫明兩者必須一致。
