# 提案:add-articulation-grid

## 為什麼要做

現在的構音記錄表把每個注音展開成一長列，列內再展開一個編輯器，每筆音對底下還掛一組音韻歷程勾選框。三個問題:

1. **太散** — 一次評估要掃過四十幾列展開式編輯器，看不到全貌。
2. **提供了不可能的選項** — ㄅ 是雙唇塞音，不可能有「塞音化」，但勾選框照列。
3. **歷程貼在錯的層級** — 音韻歷程是**整份評估的歸納**，不是單筆音對的屬性。它應該由整張表推導出來，治療師再覆寫。

## 要做什麼

- **注音格子表**:依標準注音表分欄排列（ㄅㄆㄇㄈ／ㄉㄊㄋㄌ／ㄍㄎㄏ／ㄐㄑㄒ／ㄓㄔㄕㄖ／ㄗㄘㄙ）。同欄同部位、由左至右部位由前到後——這個排列本身對治療師有意義。每個音固定三組「目標詞（國字）＋ 錯音」。
- **錯音填整個音節**:治療師照聽到的寫（例如「ㄆㄠ」），系統取第一個注音符號當錯誤音;結尾的上標 `ⁿ` 解讀成鼻音化。留白代表構音正確。
- **音韻歷程自動推導**:依 `references/phonological-processes.md` 的推導條件，從整張表算出歷程，呈現成「後置化:ㄉ ㄊ」。
- **可切換成手動**:底部一個「使用推導結果／自己選」的開關;切成自己選時出現空白區塊，治療師自己挑。

## 這次不做的事（範圍外）

- **不推導介音省略**:它是音節層次的現象，目前的記錄單位是單一符號對單一符號，推不出來。維持手動。
- **不做韻母的自動歷程**:母音鼻音化靠附加符號推得出來，其餘韻母相關歷程等記錄單位擴充後再說。
- **不動規則引擎的適用條件寫法**:歷程照樣進 `articulation.errors` 的 `processIds`，規則不用改。

## 對既有規格的影響

`add-articulation-process-tracker` 有一條需求寫著音韻歷程「只能由治療師手動指定，系統不做自動判斷」。這次要用 `MODIFIED` 正式推翻:改成預設自動推導、治療師可整份覆寫。

推導完全建立在 `references/` 的辨異徵性與部位排序上。那些內容是開發者逐項確認過的，不是模型生成的——這是這次敢做自動推導的前提。

## 技術方向

推導是**資料的函數**，不寫進儲存。存下來只會跟資料不同步;只有「不使用推導」時治療師自己選的那份才存。
