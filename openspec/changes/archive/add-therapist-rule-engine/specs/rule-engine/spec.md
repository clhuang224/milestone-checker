# Delta for rule-engine

## ADDED Requirements

### Requirement: 個案管理

系統 SHALL 讓治療師建立與切換個案，個案用暱稱或代號識別，不強制要求真實姓名等個資欄位。

#### Scenario: 建立個案

- WHEN 治療師建立一個新個案並輸入暱稱/代號
- THEN 系統會建立這個個案，並讓治療師可以切換到它繼續操作

### Requirement: 觀察與評估項目記錄

系統 SHALL 讓治療師針對目前選取的個案，勾選布林型觀察項目、填入數值型評估分數。

#### Scenario: 記錄一個個案的觀察項目

- WHEN 治療師在個案的觀察表單裡勾選一個項目或填入一個分數
- THEN 這個值會被存到該個案的 `CaseProfile`，並在畫面上立即反映

### Requirement: 規則定義

系統 SHALL 讓治療師建立規則，每條規則包含條件（勾選項目的邏輯組合，和/或數值區間判斷）跟動作（警示/歸納文字，並可選擇性附報告文字範本片段）。

#### Scenario: 建立一條規則

- WHEN 治療師在規則編輯器裡設定條件（例如「項目 A 且分數 B 大於某個值」）並填寫觸發時要顯示的文字
- THEN 系統會把這條規則存起來，之後個案的觀察資料符合條件時就會被觸發

### Requirement: 規則以 JsonLogic 格式儲存

系統 SHALL 把規則的條件存成 JsonLogic 格式的 JSON，並支援匯出/匯入整份規則集的原始 JSON 檔。

#### Scenario: 匯出規則集

- WHEN 治療師選擇匯出規則
- THEN 系統會產生一份包含所有規則的 JSON 檔案，格式可以被其他語言治療師匯入使用

#### Scenario: 匯入格式錯誤的檔案

- WHEN 治療師匯入一份結構不正確的 JSON 檔案
- THEN 系統會拒絕匯入並顯示清楚的錯誤訊息，不會靜默略過或存入壞資料

### Requirement: 規則觸發與警示

系統 SHALL 在個案的觀察資料變動後，自動用所有已啟用的規則重新評估，列出被觸發的警示/歸納。

#### Scenario: 觀察項目符合某條規則

- WHEN 個案目前的觀察項目與評估分數符合一條已啟用規則的條件
- THEN 該規則的警示/歸納文字會顯示在畫面上

#### Scenario: 停用規則不參與評估

- WHEN 一條規則被治療師停用
- THEN 即使個案資料符合它的條件，這條規則也不會顯示警示

### Requirement: 報告草稿產生

系統 SHALL 根據目前個案已觸發、且附有報告範本的規則，組出一段可編輯的文字草稿。

#### Scenario: 產生報告草稿

- WHEN 個案有一或多條規則被觸發，且這些規則附有報告文字範本
- THEN 系統會把這些範本文字組成一段草稿，治療師可以編輯並複製走

### Requirement: 純本機儲存

系統 SHALL 把所有個案資料與規則只存在瀏覽器的 `localStorage`，不使用任何後端或帳號系統;規則額外支援匯出成獨立 JSON 檔備份。

#### Scenario: 重新整理頁面

- WHEN 治療師記錄個案資料、編輯規則後重新整理頁面
- THEN 先前的個案資料跟規則都還在

### Requirement: 僅供臨床參考警語

系統 SHALL 顯示一個常駐、不會被永久關掉的提示，說明這個工具的規則與警示僅供臨床參考，不取代治療師的專業判斷。

#### Scenario: 檢視任何頁面

- WHEN 治療師檢視 App 的任何頁面
- THEN 警語都是可見的（不會被藏在選單裡，也不會只出現一次）

### Requirement: 範圍限定在語言/言語/吞嚥

系統 SHALL 在這次 change 裡，觀察項目與規則的內容只涵蓋語言、言語、吞嚥這三個類別——不包含其他治療領域。

#### Scenario: 觀察項目分類

- WHEN 檢視觀察項目/評估表單
- THEN 項目只會分在語言、言語、吞嚥三個類別下（其他領域要等之後的 change 才會加入）
