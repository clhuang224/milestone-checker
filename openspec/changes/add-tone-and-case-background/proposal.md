# 提案:add-tone-and-case-background

## 為什麼要做

開發者定案了一件事，並且順著它定案了一條規則的形狀:

> 聲調納入，自成一類。母語含台灣華語、沒有聽障、卻有聲調錯誤，就警示。

這一句話同時碰到三個目前做不到的地方:

1. **聲調在資料模型裡是半成品。** 構音格子表早就有〈聲調〉那一區，五個聲調各有三組「目標詞 ＋ 錯音」，也存得下去、也會變成 `articulation.errors` 裡的一筆。但沒有任何一條規則寫得出「有聲調錯誤」——條件列只認得目標音 id 與音韻歷程 id，要表達「聲調那一類」只能把五個聲調符號全部勾起來，而條件編輯器的選項標籤用的是 `symbol` 不是 `label`，勾選畫面上會出現五個沒有名字的 `ˉ ˊ ˇ ˋ ˙`。

   更麻煩的是反向:聲調**已經被當成音韻歷程在推導**。`deriveProcessIds()` 的 `vowelNasalization` 那條只看錯音有沒有帶鼻音化上標，不看目標音是什麼，所以在聲調列的錯音格插一個 ⁿ，會推導出一條「母音鼻音化」;`applicableProcessIds('tone3')` 也因此在聲調列的手動歷程清單裡列出它。原本移除「聲調混淆」這條歷程的理由（聲調跟部位、方式不是同一種向度），在程式裡還沒有真的落實。

2. **個案身上沒有母語。** `Case` 只有暱稱、生日、出生週數、生理性別、備註。`add-articulation-process-tracker` 當初就把「母語為國語 AND ……」列成後續 change 的候選，`add-articulation-rule-conditions` 明寫「不做母語欄位，等真的要用再開」——現在真的要用了。

3. **個案身上沒有聽力狀態。** 「沒有聽障」這個前提在資料裡完全不存在。

## 要做什麼

- **聲調自成一類，落實到推導**:目標音是聲調時，一律不推導任何音韻歷程，手動歷程清單也不提供任何一條。聲調錯誤仍然是一筆錯誤，只是它不是「歷程」這種東西。
- **聲調的錯音解析看目標音的類別**:聲調列的錯音格解析出來的必須是一個聲調，不能是句子裡第一個出現的注音符號（今天在聲調列寫「ㄆㄠˊ」，記下來的錯音是 ㄆ）。
- **個案新增母語（多選）**:內建清單 ＋ 治療師自行輸入的「其他」。清單上的語言有英文 id，自行輸入的沒有——型別怎麼切見 `design.md`。
- **個案新增聽力狀態（開關）**:未填／正常／異常三態，**沒有預設值**。
- **兩個新事實**:`case.nativeLanguages` 與 `case.hearingNormal`，都掛在 `case.` 命名空間底下。
- **條件列新增兩種對象**:「構音錯誤的類別」（聲母／介音／韻母／聲調）與「母語」。兩者都沿用既有的 `some`／`in` 形狀，不自訂 operator。
- **未填欄位的守門延伸到母語列**:母語沒填跟母語不含華語是兩件事，不能都靜靜地不觸發而不留痕跡。
- **把那條規則寫得出來**:母語含台灣華語 AND 聽力正常 AND 有聲調錯誤 → 警示。

## 這次不做的事（範圍外）

- **不做純音聽力檢查評估表。** 開發者說的是「如果有純音聽檢資料可以另外開評估表」，這次只做他說的那個開關。理由有三個，寫在 `design.md`，最短的版本是:那張表上的每一格都是這裡沒有的臨床內容（測哪些頻率、dB 怎麼記、氣導骨導差多少算傳導性、哪一組門檻算正常），而 `FormBody` 多一個 `kind` 是程式碼不是資料（`docs/ARCHITECTURE.md` 第二節），照範圍紀律本來就該是它自己的 change。
- **不由聽檢資料推導那個開關。** 這次的開關是治療師直接填的，是 `case.hearingNormal` 的唯一來源。將來那張表要不要覆寫它、兩邊不一致時聽誰的，留給那個 change 決定——先做開關不會擋住它，先猜一個關係才會。
- **不改 `articulation.errors` 裝的東西。** 聲調錯誤今天在裡面，這次之後還在裡面（除非 Q1 的答案要它出去）。已經匯出、已經在治療師之間傳過的規則檔讀的就是這個清單，靜靜改掉它裝什麼，等於靜靜改掉那些規則的意思。要讓某條規則不理聲調，是在那條規則的條件上寫清楚，不是動事實。
- **不做警示頁「有規則因為缺資料而根本沒判斷」的分辨。** 那是 `docs/畫面說明文字準則.md` 6.4 記的缺口，本案會讓它多兩個入口（母語、聽力），但補那個機制是它自己的 change。這次只把個案頁既有的那一行揭露從「生日」改成講機制本身。
- **不做「主要母語／次要母語」的區分**，也不排序。多選就是一個集合。
- **不動前置化／後置化、邊音化、介音省略**——`references/open-questions.md` 裡那幾條各自有各自的狀態，這次不碰。

## 對既有規格的影響

`add-articulation-rule-conditions` 的「不做『只算聲母錯誤』的判定」是這次要收掉的:那份 proposal 說「構音事實裡會帶著目標音的類別欄位，之後要收斂成只看聲母不用改資料結構」。這次做的正是那個收斂，只是第一個用到它的不是聲母而是聲調。`ArticulationErrorFact.targetCategory` 已經存在，不用改資料結構，只要讓條件列指得到它。

那條 starter rule `rule-articulation-therapy-referral`（四歲以上仍有捲舌音以外的構音錯誤）的行為**今天就會被一筆純聲調錯誤觸發**——聲調的 `targetPhonemeId` 不在 ㄓㄔㄕㄖ 裡面。這不是本案造成的，但本案把「聲調自成一類」寫進規格，就必須把這件事攤開來問（見下面 Q1），不能默默留著或默默改掉。

## 技術方向

不引入新套件。兩種新條件列都只用 `some`／`in`／`!` 這些 JsonLogic 原生運算子，匯出的 JSON 對其他 JsonLogic 實作照樣有意義。新事實一律掛在 `case.` 底下，項目 id 在事實物件最上層平鋪的不變量不受影響。

## 開始實作前要開發者回答的問題

依實作會撞到的順序排。**每一題都可以用一句話回答。**

### Q1. 聲調錯誤還算不算「構音錯誤」？

具體問法:現在那條 starter rule 寫的是「四歲以上仍有捲舌音以外的構音錯誤」，一個孩子如果**只有**聲調錯誤、其他音都對，這條規則今天會觸發。要維持，還是要讓構音類的規則不理聲調？

**擋住**:2.3／4.1 的語意（`articulation.errors` 要不要照類別分流）、6.1（要不要順手改那條 starter rule 的條件與文字）。答「維持」的話工作量是零。

### Q2. 純音聽檢表延到下一個 change，同意嗎？

**擋住**:整份範圍。不同意的話這份提案要重寫，因為那張表的欄位要先問過一輪臨床內容才寫得出來。

### Q3. 內建母語清單裡，華語那一項叫「華語」還是「台灣華語」？

規則寫的是「母語含**台灣華語**」，清單上如果只有「華語」，兩者就對不起來。要分成兩項（華語／台灣華語）還是一項就好？

**擋住**:2.1（`NativeLanguageId` 的成員）、6.1（規則條件要指哪個 id）。

### Q4. 「亞洲國家常見的語言」那一段要哪些語言？

請直接給清單（一行一個中文名就好，英文 id 我來取），或指定一份現成的清單讓我照抄（例如教育部新住民語文課程納入的那幾種語言，你說「用那個」就可以）。

**擋住**:2.1。這一段我不自己填——填出來的清單看起來會很像真的。

### Q5. 台灣本土語言那一段要不要含原住民族語？

要的話是一項（「原住民族語」）還是分族別？

**擋住**:2.1。

### Q6. 聽力那個開關，三個狀態的名字是什麼？

目前規劃是「未填／正常／異常」。另外:「配戴助聽器」「人工電子耳」現在要不要是獨立的第四個值，還是都算「異常」？

**擋住**:3.1（`HearingStatus` 的成員）、3.2（選項文字）。

### Q7. 那個開關由誰判定？

治療師依自己的觀察就可以填，還是必須有聽力師／耳鼻喉科的報告才填？

**擋住**:3.2 的 label 與《使用說明》的一句話。不影響型別，所以只擋文案那一項。

### Q8. 一筆「聲調錯誤」在錯音格裡怎麼寫？

一聲沒有標記符號（`tone1` 的 `symbol` 是 `ˉ`，但治療師平常不會寫它）。「該念二聲、念成一聲」這一筆，錯音格要寫什麼？

**擋住**:1.2（錯音解析）以及 UX 要不要把聲調區的錯音格換成五選一的選單。

### Q9. 輕聲算在「有聲調錯誤」裡嗎？

**擋住**:4.4（「聲調」這個類別選項涵蓋哪幾個 id）與 6.1。

### Q10. 母語多選要不要上限？

無上限、還是最多兩個？（純粹是輸入限制，不影響型別。）

**擋住**:2.2。

### Q11. 這條規則要不要當成 starter rule 出貨？

要的話，`starter-rules.ts` 的種子只在集合是空的時候才跑，所以必須把 `storage.ts` 裡**全部**的 key 一起從 `:v7` 升到 `:v8`，而**升版是作廢不是遷移**——每一個已經開過這個 app 的人，個案、課節紀錄、填答值、構音音對、音韻歷程覆寫、吞嚥嘗試、報告草稿、以及他自己新增的評估項目與自己寫的規則，全部歸零。

不出貨的話，這條規則就由治療師自己在規則編輯器裡建一次，其他人的資料一個字都不動。

**擋住**:6.1，而且只擋這一項——前面 1 到 5 節不受影響。
