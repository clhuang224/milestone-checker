# 提案:add-demo-case-seeds

## 為什麼要做

兩個實際遇到的問題:

1. **改了預設內容，既有使用者看不到。** seed 只在集合為空時才跑，所以上一個 change 拿掉「構音錯誤音數」、加上新的預設規則之後，瀏覽器裡已經有舊資料的人完全不受影響，還是看到舊的那一套。這個專案還在 PoC 階段，沒有要保護誰的資料，不需要寫遷移程式——直接把 `localStorage` 的 key 升版，舊資料整包作廢就好。
2. **空白的 app 看不出東西長怎樣。** 現在第一次打開只有觀察項目、規則、音韻歷程三份目錄，個案是空的，要自己一筆一筆敲才看得到警示跟報告草稿長什麼樣子。附一個示範個案可以直接看到整條鏈的結果。

## 要做什麼

- **`localStorage` key 全部升到 v2**，舊資料不遷移、直接作廢。
- **附一個示範個案「小切」**（改寫、簡化過的內容，不是真實個案），包含生日與構音音對記錄，一打開就能看到「四歲以上仍有捲舌音以外的構音錯誤」這條規則被觸發、報告草稿被組出來。
- 示範個案跟其他預設內容一樣**只在個案清單為空時才 seed**，刪掉之後不會再冒出來。

## 這次不做的事（範圍外）

- **不做資料遷移**:PoC 階段的明確取捨，升版就是清空。之後若真的要保留使用者資料，要另外開 change 做遷移。
- **不標示「這是示範資料」**:示範個案就是一筆普通個案，治療師可以直接改或刪。個案本身不像規則/觀察項目那樣需要審核關卡——它不是臨床判斷依據，只是一組讓畫面有東西可看的資料。
- **不做成人後天個案**:梅姐那筆牽涉到吞嚥測試記錄與言語分級量表，資料模型還沒有，另外開 change。

## 技術方向

生日**由 seed 執行當天回推**，而不是寫死日期——寫死的話示範個案會愈長愈老，「8 歲 0 個月」這個標題過幾年就對不上，用來示範年齡規則也會失去意義。
