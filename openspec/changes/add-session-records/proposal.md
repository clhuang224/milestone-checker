# 提案:add-session-records

## 為什麼要做

導覽長錯了。頂層是 `個案 / 規則 / 音韻歷程`，而觀察項目被寫死成 `語言 / 言語 / 吞嚥` 三類——而開發者判定這個三分法本來就只是概略。

實際的後果:

- **看到的項目跟正在做的事無關。** 觀察項目是一份全域扁平清單，整份交給表單渲染。一個吞嚥個案照樣被問「表達性詞彙量明顯落後同齡」，一個成人失語個案照樣被問「進食時有沒有流口水」。
- **構音跟吞嚥根本不走那條路。** 它們各有自己的畫面與資料模型，跟那三個分類毫無關係。所以「分類」這個概念只涵蓋了九個項目，卻假裝是整個 app 的骨架。
- **「這一次做了什麼」看不出來。** 場次只是一個下拉選單，選項全都只顯示日期。

真正缺的實體是**評估表**:治療師心裡的單位是「這次做了構音評估」「這次寫了 SOAP」，不是「這次填了三個 language 類的項目」。

## 要做什麼

- **課節紀錄**取代場次。一筆課節紀錄有日期與備註，底下**掛一到多張表**;掛哪幾張在建立時勾選，之後可改。
- **表是目錄裡的一筆。** 掛了 SOAP 就是治療紀錄，掛了構音評估表就是評估，兩個都掛就是同一次回診做了兩件事——**「評估或治療」不是紀錄上的欄位，是掛了哪些表**。
- **個案頁改成基本資料 ＋ 課節紀錄表格。** 表格欄位:日期、內容（掛了哪些表）、當時年齡、重點。點一列進入該筆紀錄。
- **一筆紀錄裡用頁籤在表之間移動**，各表一條路由。
- **導覽改成 個案一覽 / 評估表一覽。**

## 這次不做的事（範圍外）

- **不做 SOAP、吞嚥、自訂項目三種表的內容**——這次只做容器與導覽，構音表是唯一接進來的表。其餘各自一個 change。
- **不做評估表的項目與條件編輯畫面。** 評估表一覽這次只列出表與其掛載數，編輯留到自訂項目表那個 change。
- **不做跨課節的比較與進步追蹤。** `add-assessment-sessions` 當初就排除在外，新的表格導覽會讓人期待它，但仍不在這次。
- **不做表的版本化。** 表改了項目之後舊紀錄看到哪一版，是未決問題;PoC 階段先不處理。

## 影響

- **既有的九個觀察項目整批丟掉。** 它們是模型生成的示意內容，不對應任何一份真實的表。
- **`categoryId` 移除。** 全 app 只有一處在讀它（觀察表單的分區標題），而那個分區正是這次要換掉的東西。
- **`CLAUDE.md` 的「範圍限定在語言/言語/吞嚥」與對應的規格需求要改寫**成「只做目前有的表」。
- **規則不受影響。** 前提是項目 id 維持全域唯一、且在事實物件裡維持平鋪——已匯出的規則檔寫的是 `{"var": "drooling"}`，這個形狀不能動。這是整個改版最該保護的不變量。

## 技術方向

儲存版號升 v5、舊資料作廢，沿用既有的 PoC 取捨。

表的內容用 `body.kind` 區分:`articulationGrid` 這次就位，`soapNote`／`swallowTrials`／`itemList` 之後補。**不要把表單建構器做到通用得足以表達構音格子表**——格子表留在程式碼裡，只是多一個目錄項目讓它跟別的表一樣被找到。
