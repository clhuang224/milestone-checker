## 缺陷

- [ ] **`Case.note` 與 `SessionRecord.note` 沒有畫面。** 示範個案「小美」帶著一句備註，任何地方都看不到。
- [ ] **`itemList` 與 `soapNote` 被拿掉時不會清資料。** `setRecordForms()` 只處理構音與吞嚥。`itemList` 的填答值放在一份不分表的 `RecordProfile` 裡，拿掉其中一張會把另一張的答案一起帶走——等那張表真的做出來再決定怎麼切。
- [ ] **吞嚥還缺四塊。** 資料路徑本身通了（`Storage` 集合、`buildFacts()` 的 `swallowing.trials`、規則評估），但:(1) `starter-swallow-catalogue.ts` 的質地／標記／單位常數在 `src/` 裡沒有任何地方 import，也沒有 seed;(2) 規則編輯器做不出 trial 條件列——`condition-editor.ts` 只認 `row`／`set`／`group`;(3) 沒有填寫嘗試的畫面;(4) 所以除了測試以外沒有東西產生得出一筆 `SwallowTrial`。

- [ ] **事實模型分不出「測過而且正確」與「沒測」。** `buildFacts()` 只送出 `articulation.errors`，沒有任何事實代表某個音測過且正確，所以規則面對「ㄗ 沒測」與「ㄗ 測了是對的」會得到相同答案。格子表本身分得出來（〈目標詞〉有填就留著記錄），是事實層漏掉了。
- [ ] **〈警示〉頁的「目前沒有規則被觸發」蓋住兩件不同的事**——規則都跑過但不成立，以及規則因為欄位沒值而根本沒判斷。`evaluateCondition()` 對缺值的比較欄位一律回 false。沒填生日只是今天唯一看得到的症狀，之後每加一張項目式的表就多一個入口。要修的是機制不是欄位。
- [ ] **畫面上沒有任何地方連到《使用說明》。** 見 `docs/screen-text-policy.md`——準則把「該講的講、其餘交給說明書」當成前提，但說明書現在找不到。

## 要開發者決定

- [ ] **要不要加一個拉丁字型？** 中文不加——CJK 字型是四 MB、上百個分片，而系統字（PingFang TC／
      微軟正黑）跟 Noto Sans TC 是同一個字族，看不出差別。但一個 15–25 KB 的拉丁 subset 放在
      `--font-sans` 最前面，會讓標題、頁籤與數字欄位（日期、cc 數、成功率）明顯緊實。選哪一個
      字體是設計決定。

- [ ] `references/open-questions.md` 剩下的待議事項:邊音化與 ㄋ／ㄌ 互換（開發者要求延後討論）、蒟蒻果凍要不要另立標記、台灣本土食物的等級對照（兩者都延後）。前置化／後置化的對照表**開發者決定不做**，維持手動貼標籤。

## 種子個案

第一版做三位:小美（8 歲，已完成）、小小華（2 歲，語言發展）、一位成人吞嚥個案。名字與年齡已定案，

比空著更糟。

### 小小華（兒童語言評估表，走語言發展路線）

- [ ] 這張表要有哪幾個項目？三到五個就夠示範。

- [ ] 哪一個項目、在幾個月以上，要跳警示？這個門檻只能開發者定——公開文獻裡的切點綁在有版權的
      測驗上。
- [ ] 那條警示用實齡還是矯正齡？兩個事實都在，系統刻意不替使用者選。
- [ ] 那條警示的畫面文字與報告草稿文字各寫什麼？

### 成人吞嚥個案

      示範資料最好兩種各出現一次。
- [ ] 要不要有一條吞嚥規則被觸發？條件、警示文字、報告文字各一句。
