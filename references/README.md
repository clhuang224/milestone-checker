# references — 臨床參考資料

這個資料夾放**語言治療領域的知識**，跟程式碼分開。用途有三個:

1. **可查詢** — 想知道系統憑什麼判斷 ㄉ→ㄍ 是後置化，來這裡查，不用讀 `.ts`。
2. **可交付檢查** — 這些表格可以直接貼給另一位治療師看，請他挑錯。
3. **可追溯** — 在 git 裡看得出哪一格什麼時候被誰改成什麼。

## 這裡的內容從哪裡來

**一律由開發者提供。** 這個專案由 Claude Code 驅動開發，但臨床內容不是模型能自己生成的東西——生出來的表格看起來很像真的，錯了卻沒有任何跡象。所以規則是:模型不確定就拆成小問題逐項問，不自己填。

這條規則是踩過坑才訂的。專案早期的聲母辨異徵性表、音韻歷程清單、年齡門檻全部是模型生成的，當時靠「標記為佔位、待治療師審核」當緩衝。那個標記後來拿掉了——審核的人就是開發者本人，標記只是噪音，被標記的內容照樣是編的。現在改成:**沒確認過的內容就不寫進去**。

## 不引用標準化測驗

坊間的標準化語音測驗有版權，內容不能抄進這個專案。這裡的臨床定義是**開發者依自己的臨床經驗寫下的**，不是文獻引用。

這跟規則的 `sourceNote` 是同一種性質:內容的權威來自寫下它的治療師，不是來自某份出版品。所以交給別的治療師檢查時，問的是「你同不同意」，不是「這出自哪裡」。

## 跟程式碼的關係

`references/` 是給人看的、`src/app/data/` 是給程式讀的，兩邊放同一份資料。要改的時候**先改這裡**，再同步過去；有測試比對兩邊是否一致，改到不一樣會紅燈。

- `taiwan-mandarin-consonants.md` ↔ `src/app/data/zhuyin-inventory.ts`
- `taiwan-mandarin-vowels.md` ↔ `src/app/data/zhuyin-inventory.ts`
- `phonological-processes.md` ↔ `src/app/data/starter-articulation-processes.ts`
- `swallowing-consistencies.md` ↔ `src/app/data/starter-swallow-catalogue.ts`

表格用英文 id 那一欄對應程式碼裡的值，中文欄位是畫面顯示用的。

## 發現錯誤怎麼辦

直接改這裡的表格，然後告訴開發者要同步程式碼。不要只改 `.ts`——那樣文件會過期，下一個人查到的就是錯的。
